# OSTRAM LAC - Energy System Optimization Model

OSeMOSYS-based energy optimization modelling system for Latin America and the Caribbean.

## Description

This project implements an automated pipeline to run energy optimization models with OSeMOSYS (Open Source Energy Modelling System). The system supports several solvers (GLPK, CBC, CPLEX, Gurobi) and is designed to guarantee full reproducibility of the results.

## Main Features

- **Automated pipeline**: Complete workflow management with DVC (Data Version Control)
- **Multiple solvers**: Support for GLPK, CBC, CPLEX and Gurobi
- **Guaranteed reproducibility**: Configurable seeds for deterministic results
- **Performance measurement**: Built-in timer to monitor execution times
- **Automatic environment management**: Automatic creation and update of the Conda environment

## Repository Structure

The repository is organised in three top-level folders:

```
OSTRAM-LAC/
├── inputs/    # Data and configuration maintained by hand (config/, data/, OG_csvs_inputs/,
│              # A1_Outputs/, A2_Extra_Inputs/, Miscellaneous/, reference/, tx_chain/)
├── scripts/   # Source code (pipeline/, common/, dashboard/, tools/, fix_dispatch/,
│              # tx_chain/, tests/, experimental/)
└── outputs/   # Everything regenerated by the pipeline (A2_Output_Params, Executables,
               # Figures, logs, model, RELAC_TX_*.csv)
```

General rule:
- **`inputs/`** = maintained by hand, never regenerated automatically.
- **`outputs/`** = regenerated by the pipeline; do not edit by hand.
- **`scripts/`** = code.

Paths in the YAML configuration files are always relative to the repository root, regardless of the directory the script is invoked from.

`scripts/common/relac_paths.py` is the single source of truth for the layout: any script that needs a path under `inputs/` or `outputs/` must import it from there instead of hard-coding it.

## System Requirements

- Windows 10 or higher
- Git for Windows
- Miniconda or Anaconda
- At least one solver: GLPK, CBC, CPLEX or Gurobi (GLPK and CBC are included in the Conda environment through `environment.yaml`; CPLEX and Gurobi are installed separately)

## Quick Start

```bash
# Clone the repository
git clone https://github.com/Climate-Lead-Group/OSTRAM-LAC.git
cd OSTRAM-LAC

# Run the model (from an Anaconda Prompt)
python run.py
```

The `run.py` script automatically handles:
- Creation of the Conda environment
- Installation of dependencies
- Execution of the full pipeline
- Generation of the output files

## Output File Structure

Results are written to `outputs/` with the following files:
- `RELAC_TX_Inputs.csv` / `RELAC_TX_Inputs_YYYY-MM-DD.csv`
- `RELAC_TX_Outputs.csv` / `RELAC_TX_Outputs_YYYY-MM-DD.csv`

The date-stamped files keep a complete history of runs.

## Configuration

The main configuration file is `inputs/config/Config_MOMF_T1_AB.yaml`, where you can set:
- The solver to use (`solver: 'cplex'`)
- The number of threads for commercial solvers
- Seeds for reproducibility
- Capital annualization (`annualize_capital`)

## Technology-Country Matrix

The system includes a configurable matrix that specifies which technology-country combinations are processed, and that can merge the combined-cycle and open-cycle gas technologies (CCG and OCG) into a single natural gas technology (NGS).

### Usage

1. **Generate the matrix**:
   ```bash
   python scripts/pipeline/A0_generate_tech_country_matrix.py
   ```
   This creates `Tech_Country_Matrix.xlsx` with the following sheets:
   - **Matrix**: YES/NO grid for each technology-country combination
   - **NGS_Unification**: Settings to merge CCG + OCG → NGS
   - **Aggregation_Rules**: Aggregation rules (avg/sum/disabled)
   - **Tech_Reference**: Technology descriptions
   - **Country_Reference**: Country descriptions

2. **Configure the matrix**:
   - In the **Matrix** sheet: change YES/NO to enable/disable combinations
   - In the **NGS_Unification** sheet: set YES/NO to enable the CCG+OCG→NGS merge

3. **Run the preprocessing**:
   ```bash
   python scripts/pipeline/A1_Pre_processing_OG_csvs.py
   ```
   The script automatically applies:
   - Filtering by the technology-country matrix
   - Natural gas (NGS) unification (if enabled)
   - Region consolidation
   - Cleanup of PWR technologies

## Secondary Technologies Editor

The project includes a system that makes it easier to edit secondary technologies (Secondary Techs) in the parametrization files, with support for automatic integration of data from the Latin American Energy Organization (OLADE).

### Using the Editor

1. **Generate the editing template**:
   ```bash
   python scripts/pipeline/D1_generate_editor_template.py
   ```
   This creates `Secondary_Techs_Editor.xlsx` with two sheets:
   - **Instructions**: For manual editing with dropdown lists
   - **OLADE_Config**: Settings for automatic integration of OLADE data

2. **Manual editing** ("Instructions" sheet):
   - Select: Scenario (BAU, INV, OPT, or ALL)
   - Select: Country, Technology (Tech.Name) and Parameter
   - Enter the values for the desired years (2021-2050)
   - The "Tech" column is filled in automatically with VLOOKUP

3. **OLADE integration** ("OLADE_Config" sheet):

   Populates parameters automatically from OLADE data.

   | Parameter | Description |
   |-----------|-------------|
   | `ResidualCapacitiesFromOLADE` | YES/NO - Enable OLADE integration for installed capacity (ResidualCapacity) |
   | `PetroleumSplitMode` | OIL_only or Split_PET_OIL - Petroleum split mode |
   | `DemandFromOLADE` | YES/NO - Enable OLADE integration for electricity demand |
   | `ActivityLowerLimitFromOLADE` | YES/NO - Enable OLADE integration for TotalTechnologyAnnualActivityLowerLimit |
   | `ActivityUpperLimitFromOLADE` | NO/YES_ALL/EXISTING_ONLY - Control updates of TotalTechnologyAnnualActivityUpperLimit |

   **PetroleumSplitMode**:
   - `OIL_only`: Assigns all petroleum capacity to OIL (fuel oil)
   - `Split_PET_OIL`: Splits between PET (diesel) and OIL (fuel oil + bunker) using the proportions in `Shares_PET_OIL_Split.xlsx`

   **DemandFromOLADE**:
   - When enabled, updates electricity demand in `A-O_Demand.xlsx` using OLADE generation data
   - Growth rates per country are set in the `Demand_Growth` sheet
   - Formula: `Demand(year) = Demand(2023) × (1 + rate × (year - 2023))`

   **ActivityLowerLimit and ActivityUpperLimit**:
   - When enabled, they automatically populate the activity limits in `A-O_Parametrization.xlsx`
   - Uses OLADE electricity generation data combined with technology shares from `Shares_Power_Generation_Technologies.xlsx`
   - Optional renewability targets are set in the `Renewability_Targets` sheet
   - Custom technology weights are set in the `Technology_Weights` sheet
   - LowerLimit formula: `LowerLimit(tech,year) = Demand × normalized_share`
   - UpperLimit formula: `UpperLimit(tech,year) = LowerLimit(tech,year) × 1.05`
   - **UpperLimit modes**:
     - `NO` — Does not update UpperLimit
     - `YES_ALL` — Updates UpperLimit for all technologies
     - `EXISTING_ONLY` — Only updates technologies that already have UpperLimit defined and Projection.Mode = "User defined"
   - Includes automatic validation against available capacities
   - See the `Documentation` sheet of the editor for full details of the calculation and validation

4. **Additional editor sheets**:

   `Secondary_Techs_Editor.xlsx` also includes:
   - **Renewability_Targets**: Defines renewable % targets per year for each country/scenario (used by Activity Limits)
   - **Technology_Weights**: Defines a custom distribution of renewable and non-renewable technologies
   - **Scenarios_Demand_Growth**: Sets demand growth rates per scenario and country
   - **Documentation**: Complete technical documentation of the Activity Limits calculation and validation

5. **Apply the changes**:
   ```bash
   python scripts/pipeline/D2_update_secondary_techs.py
   ```

### System Features

- **Dropdown lists**: Make it easy to select scenarios, countries, technologies and parameters
- **Tech.Name → Tech mapping**: Automatic conversion of descriptive names to technology codes
- **OLADE capacity integration**: Automatic population of ResidualCapacity from installed-capacity data
- **OLADE demand integration**: Automatic population of electricity demand from generation data
- **OLADE Activity Limits integration**: Automatic population of TotalTechnologyAnnualActivityLowerLimit and UpperLimit
- **Unit conversion**: MW → GW (capacity), GWh → PJ (demand and activity)
- **Flat values (capacity)**: The same capacity value is used for every year
- **Linear growth (demand and activity)**: Configurable growth rate per country
- **Activity Limits validation**: Automatically checks that the limits do not exceed the available capacity
- **Renewability targets**: Interpolation system to reach renewable % targets
- **Automatic backups**: One backup per scenario before applying changes
- **Projection.Mode**: Set automatically to "User defined" when values are modified
- **Detailed logs**: Complete record with the country identified in each operation

## Country Management Tools

### Country Data Validator

Checks that a country has all the required data in the OSeMOSYS input CSV files.

```bash
python scripts/tools/Z_validate_country_data.py                  # Validate all model countries
python scripts/tools/Z_validate_country_data.py --country ARG    # Validate one country
python scripts/tools/Z_validate_country_data.py --country NCC --report  # Generate a detailed report
```

**Checks performed:**
- Presence in the sets (TECHNOLOGY, FUEL, EMISSION, STORAGE)
- Minimum number of technologies per prefix (PWR, MIN, RNW)
- Data in all required parameters (costs, capacity, factors, ratios, etc.)
- Expected fuel patterns per country

### New Country Template Generator

Creates a set of CSV files with the minimum structure needed to add a new country, using an existing country as reference.

```bash
python scripts/tools/Z_generate_country_template.py                              # Reads config from YAML
python scripts/tools/Z_generate_country_template.py --new NCC --ref ARG -i BOL PRY  # Override from the command line
```

**Configuration** (`template_generation` section of `Config_country_codes.yaml`):

| Parameter | Description |
|-----------|-------------|
| `new_country` | 3-letter code of the new country |
| `reference_country` | Existing country to clone data from |
| `region` | Region code (default: XX) |
| `interconnections` | List of neighbours for interconnections (empty = no interconnections) |

**Features:**
- Generates CSVs in `templates/{CODE}/` without modifying the original files
- Dynamic handling of interconnections: supports more, fewer, the same number of, or zero interconnections relative to the reference country
- Correct transformation of fuel and mode-of-operation codes for TRN technologies
- Includes a `merge_into_inputs.py` script in the generated folder to ease the integration
